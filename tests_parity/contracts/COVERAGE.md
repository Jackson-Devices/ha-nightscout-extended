## Fork main and PR 10

On a v1 treatment GET the stock serializer applies JavaScript `Number()` to `carbs` and `insulin`.
It leaves `duration` alone. The v3 generic search resolves document dates and preserves the stored
JSON types of these quantities. Comparisons use each endpoint’s actual response, including when a
published numeric schema disagrees. ## Stock witnesses and parity verdict

- Stock mounts its v1 router inside v2. The stock middleware handles `.json` suffixes. Mounted entries, SGV subtype, treatments, device status, profile and status aliases resolve to their published v1 operations. V3 collection reads use the documented generic operation and the selected collection's own schema. The stock probes exercise profile and settings permissions. The validator also recognizes the documented food collection. The v3 status result supplies API permissions, and the v3 settings collection has its own permission requirement. [V2 mount](https://github.com/nightscout/cgm-remote-monitor/blob/9cd304f78a5c12401c9711cbd56d2a12eaca0632/lib/api2/index.js), [legacy format alias](https://github.com/nightscout/cgm-remote-monitor/blob/9cd304f78a5c12401c9711cbd56d2a12eaca0632/lib/middleware/express-extension-to-accept.js), [v3 search permissions](https://github.com/nightscout/cgm-remote-monitor/blob/9cd304f78a5c12401c9711cbd56d2a12eaca0632/lib/api3/generic/search/operation.js#L13-L26)
- The calculated properties implementation selects keys from the sandbox, guarded by both entries and treatments read permissions. The source-only shape checks cover consumed field types, paired clocks and explicit omissions. PR 2 observed synthetic values of 180 mg/dL, +12 mg/dL delta, IOB 1.375 U, COB 7.5 g, current basal 0.85 U/h, and actual AR2 points at their native target timestamps. The separate native permission debug GET supplies allow/deny controls. [Properties handler](https://github.com/nightscout/cgm-remote-monitor/blob/9cd304f78a5c12401c9711cbd56d2a12eaca0632/lib/api2/properties.js#L13-L52), [permission handler](https://github.com/nightscout/cgm-remote-monitor/blob/9cd304f78a5c12401c9711cbd56d2a12eaca0632/lib/authorization/endpoints.js#L21-L29), [debug handler](https://github.com/nightscout/cgm-remote-monitor/blob/9cd304f78a5c12401c9711cbd56d2a12eaca0632/lib/authorization/endpoints.js#L109-L113), [PR 2 live observations](https://github.com/Jackson-Devices/ha-nightscout-extended/blob/555848b1/docs/nightscout-15.0.6-results.md#L23-L31)
- V1 source-backed query extensions cover the exercised duration sort and access-token presence. The published status and treatment declarations use a catch-all error schema. An unlisted HTTP status remains an unsupported response. V3 explicit 401/403 cases use their original operation schemas and must carry a matching native status field. Successful v3 reads must carry the native envelope and preserve the consumed fields. The independent wire permission probes establish authorization equivalence. [Legacy treatment sort](https://github.com/nightscout/cgm-remote-monitor/blob/9cd304f78a5c12401c9711cbd56d2a12eaca0632/lib/server/treatments.js#L105-L121), [stock v3 search parameters](https://github.com/nightscout/cgm-remote-monitor/blob/9cd304f78a5c12401c9711cbd56d2a12eaca0632/lib/api3/generic/search/input.js#L50-L82)
- Stock v1 treatment nulls, numeric `timeFormat`, `alarmTypes` values, and stock device-status `loop` objects are known differences from the published response schemas. V3 can return a list where the published `DocumentArray` declares an object, and older records can lack the required `app` field. When such responses pass native checks, the suite retains the observed route, instance pointer, schema pointer, and validation keyword as Swagger evidence. The comparison with Home Assistant uses the original native response. Wrong requests, unverified schemas, unsupported operations or statuses, incorrect native envelopes, and wrong consumed fields fail the test.
