# Nightscout numerical review

Use this checkout to investigate whether a Nightscout observation keeps its value, unit, measurement time and availability on its way to Home Assistant and the bundled card. The fixtures use synthetic glucose and pump records. All endpoints for native replay belong to the disposable test server. The release candidate is [01ebf02](https://github.com/Jackson-Devices/ha-nightscout-extended/commit/01ebf02d5bcc0275412e457f0f4c2821d14ea67b). The release rehearsal and the previously frozen comparisons can be read at [the QA parent](https://github.com/Jackson-Devices/ha-nightscout-extended/blob/989c38952eed869fcd323af64daabd9f705a424d/evidence/PREVIEW/batch-pass.json).

## Stage the tools

Check out the fork’s `qa/math-review` branch on Linux x86_64 with glibc. Run these commands from the repository root. Use a new scratch directory outside the checkout. Setup downloads the pinned public Python, uv, Node and wheel artifacts. The second command rechecks the installed packages and imports offline.

```bash
SCRATCH="$(mktemp -d)"
STATE="$SCRATCH/math"
python3 tests_contract/math_review/stage.py --state "$STATE"
python3 tests_contract/math_review/stage.py --state "$STATE" --check
export PATH="$STATE/bin:$PATH"
"$STATE/ha/bin/python" -m pytest -q -c tests_ha/pytest.ini -p no:cacheprovider --collect-only tests_contract/math_review
python3 tests_contract/math_review/mutations.py plan
python3 tests_contract/math_review/mutations.py mutmut-plan
```

The HA interpreter includes pytest, the HA custom-component fixtures, the existing time freezer and Hypothesis. The mutation interpreter has the same HA stack plus mutmut. Both use CPython 3.14.4. A stock Node child loads the actual bundled card, registers it against a minimal DOM, invokes its render path at a supplied clock and observes text, colour and SVG output. This measures the card’s behavior through code and leaves browser layout and device accessibility for a separate review. Standard-library `Fraction` supplies exact quantity comparisons. SQLite supplies an independent store for the history model and `zoneinfo` supplies actual timezone transitions.

## Run the review

The following commands execute the new designs. The stateful test generates and shrinks event sequences. Retain the minimized sequence from any failure together with the Hypothesis version. Use the Linux setup above for either cloud host. The native runner additionally needs Docker Engine and Compose with access to the pinned image digests. It creates its own disposable loopback site and disposable read-only integration identity.

```bash
"$STATE/ha/bin/python" -m pytest -q -c tests_ha/pytest.ini -p no:cacheprovider \
  tests_contract/math_review/test_math_contract.py \
  tests_contract/math_review/test_projection.py \
  tests_contract/math_review/test_ordered_state.py
python3 tests_contract/math_review/native_replay.py --state "$STATE" --output "$SCRATCH/native" --pull
python3 tests_contract/math_review/mutations.py run --state "$STATE" > "$SCRATCH/named-mutations.json"
python3 tests_contract/math_review/mutations.py mutmut --state "$STATE" > "$SCRATCH/mutmut.json"
```

`native_replay.py` owns the native pytest input and drives one paired batch. Its default is the same source readings in public legacy and protected v3. The 180 mg/dL case includes a preceding reading to give real AR2 a usable input. The 80 mg/dL case sends one reading and observes the missing curve. Actual server thresholds and forecast points travel in the evidence. For a reduced replay select `--mode public` or `--mode protected`, and `--case NATIVE-HIGH-EQUAL-AR2` or `--case NATIVE-LOW-EQUAL-NO-AR2`. Supply a new output path per run. Read its `summary.json` alongside the per-case provider and HA/card observations.

Use `mutations.py list` for stable case IDs. `run --state "$STATE" --case card-target-equality` selects a single named change for diagnosis. Run the catalogue against a clean committed checkout so its scratch copy matches the stated target. Preserve a nonzero exit and its JSON evidence. The optional `mutmut` command explores a bounded Python target. Judge its output separately from the named controls.

## What to check first

| Case | Synthetic input and change | Observable result and authority |
| --- | --- | --- |
| Display units and alarm bands | Set the example site’s upper in-range boundary to 180 mg/dL. Replay 179, 180 and 181 with the same age and thresholds. Change the HA display unit. | The example site puts 180 in range and 181 high. At one decimal both can display as 10.0 mmol/L. Keep the HA state string before formatting, the card’s text, its actual colour/class and the source-derived class. A match between two text strings cannot establish agreement about the band. Repeat around the other three boundaries and with site overrides. |
| Signed difference and sibling units | Set the current glucose to mmol/L and the change or forecast entity to mg/dL, then reverse the unit assignments. Include zero, plus and minus values and exact half steps. | Trace each value with the unit on its own entity. The displayed change or forecast must represent the same quantity in the unit presented to the user. Capture the signed glyph and rounded magnitude. JavaScript rounds negative halves toward positive infinity. Keep the original signed change available for the comparison. |
| Source anchor and partial AR2 | With a 12:00 UTC source reading, deliver a 12:15:02 forecast point and a 12:30:02 point. Move only the poll or inject a later raw SGV. Remove one point, then both. Move a point to 179,999, 180,000 and 180,001 ms from its target. | Compare each horizon independently against the closest finite supplied point to the **v2 bgnow** measurement plus its horizon, with an inclusive 180,000 ms tolerance. Return the actual point’s time and server-supplied value. A missing horizon has no numeric value. The Nightscout producer offsets predicted points by 2,000 ms. |
| Freshness and availability for HA users | Advance the browser across the configured stale minute with the HA bundle held fixed. Separately advance the HA poll and then deliver fresh data. | Record glucose, forecast, last reading, their attributes, and stale styling separately. A frontend age transition cannot update an HA state that an automation consumes. Where a published entity contract has no expiry, report the observed age and availability as a review decision. |
| Quiet ticks, correction and backfill | Ingest A at 12:00 and C at 12:10. Poll with zero rows, restart, then deliver B measured at 12:05. Replay B, correct B by ID, and inject an explicit v3 tombstone. Force a failure before the store commits and retry. | A quiet poll keeps C and its original timestamp. B belongs between A and C. Replaying one ID cannot duplicate it. Independent source IDs with equal timestamps both survive. A v3 tombstone has an explicit meaning. A legacy response omitting B does not establish deletion. Compare committed rows after restart, the selected current pair and completeness of the requested interval. |
| Source quality and exact time | After a valid pair, send raw values 38, 39, 40 at distinct millisecond times. Present a future pair at 59,999 ms and exactly 60,000 ms, varying corroborating time and value independently. | Separate retained raw readings from eligibility as the current reading. The pinned Nightscout current-glucose plugin filters for values greater than 39. Assert the history action’s integer milliseconds independently of a timestamp sensor displayed to whole seconds. |
| Pump and maintenance | Pair an upload received now with pump contact 3,599,999, 3,600,000 or 3,600,001 ms ago. On 29 March 00:30 UTC to 02:30 UTC is two elapsed hours. |
| Dimensions and optional fields | Publish different recognizable values for insulin on board (U), carbs on board (g) and basal rate (U/h). Change one, remove another, and keep glucose and forecasts usable. | Trace each upstream field to its own entity, its unit and its availability. Keep a legitimate reported zero separate from an unavailable field. The oracle compares the **reported** quantities and forecast points. It never calculates a dose, basal requirement, carbohydrate requirement or physiological prediction. |

## Additional investigations with concrete expected evidence

These designs complement the executable cases. Record them as unrun until their inputs have gone through the specified layer.

1. **Indistinguishable display text.** HA uses 18.016 mg/dL per mmol/L. Its unrounded values for 180 and 181 are exactly 5625/563 and 22625/2252 mmol/L. The candidate card uses 18.0182 to reconstruct mg/dL. Multiplying the first value back gives approximately 180.02198. Inspect the native HA state to locate the first loss of precision or change of band. If the wire state retains precision, look at the card’s conversion. If the state is already rounded, record which source information would be needed to classify both inputs. [HA glucose converter](https://github.com/home-assistant/core/blob/2026.10.4/homeassistant/util/unit_conversion.py#L209-L219) · [Product card](https://github.com/Jackson-Devices/ha-nightscout-extended/blob/01ebf02d5bcc0275412e457f0f4c2821d14ea67b/custom_components/nightscout_extended/www/nightscout-glucose-card.js#L454-L505)
2. **Prediction provenance and ties.** Supply points equidistant either side of one target, with visibly different values. Reverse their arrival order. Record both point times, source time, selected value and tie policy. Give two different values the same forecast timestamp and record the ambiguity separately. With an earlier unchanged bgnow anchor and later raw SGV, verify that a point does not move to the later reading. Native differential replay obtains the actual server curve. Missing or sparse curves are a valid upstream result when evidence supports it. [Nightscout AR2](https://github.com/nightscout/cgm-remote-monitor/blob/15.0.6/lib/plugins/ar2.js#L246-L300)
3. **Missing history versus a flat trace.** Request the same older interval online, then offline from cache, then extend the request into dates never fetched. Keep the exact requested half-open interval, returned coverage and raw points. Verify the originally cached points keep their timestamps and any unproven interval is identified. Inspect chart line breaks at missing coverage. A response that actually covers an empty interval is different from an unavailable interval. A storage failure before checkpointing must leave a retryable cursor. [Product history store](https://github.com/Jackson-Devices/ha-nightscout-extended/blob/01ebf02d5bcc0275412e457f0f4c2821d14ea67b/custom_components/nightscout_extended/sgv_history.py)
4. **Server filtering and interpolation.** Feed two real NS buckets with more than one SGV per bucket. Contrast latest value with bucket mean. Change only the spacing of the buckets across nine minutes and observe the reported delta. Supply a sentinel alongside a valid observation, then withhold the valid observation. Compare bgnow, delta and AR2 against each of their real server properties. Keep raw history and displayed current selection in separate fields. [Nightscout bgnow and delta](https://github.com/nightscout/cgm-remote-monitor/blob/15.0.6/lib/plugins/bgnow.js#L90-L172)
5. **Clock and page metamorphisms.** Translate all measurement, upload, poll and forecast timestamps together by one day on a synthetic fixed-offset clock. Values, order, eligibility and durations should be invariant. Next move only the server-write time across a page boundary, then only the browser clock. Those changes may alter pagination and frontend age respectively. Compare final records by source identity and original time. Repeating a page or changing how equivalent complete pages are split must preserve their committed contents. Document which observation changed first.
6. **Pump-contact ownership.** Use two uploaders with overlapping upload windows. Let the bound uploader report 0 U at exactly one hour, and let another uploader report a newer nonzero balance. Move the bound contact one millisecond earlier while keeping both uploads fresh. Record the selected uploader, contact time, quantity and availability, and whether the unrelated new message affects the answer. AAPS writes its observed pump contact to `pump.status.timestamp` and its serialization clock to `pump.clock`. The pinned AAPS producer exports a whole-unit reservoir. Fractional fixtures exercise preservation of wire precision for other accepted numeric inputs. [AAPS 4.0.0 pump status producer](https://github.com/nightscout/AndroidAPS/blob/f77abd9b82b308e8fc330da0d7a31370fb4a0f49/implementation/src/commonMain/kotlin/app/aaps/implementation/pump/PumpStatusProviderImpl.kt#L91-L110)
7. **Wire unit versus site preference.** Keep the same explicitly mg/dL source document, change the Nightscout display preference, then override a single HA entity's unit. Capture the raw API value and unit, history's canonical mg/dL, the actual HA state/unit and the card label. The input quantity and event time are invariant under both preference changes. Repeat with a fixture explicitly marked mmol/L on a route that accepts it, and document which component normalizes it. A double conversion is visible before display rounding.

## Evidence for the review

Use one row per distinct discrepancy. State the case or Hypothesis replay selector, checkout, seed or minimized operation sequence, API mode, input ID, quantity/unit and original measurement milliseconds. Record any independent server-write, pump-contact, poll and browser times used. Retain the source response fields, exact expected value/unit and permitted rounding stage, HA state/unit/attributes, history rows or missing intervals, and card text/class. State which layer first diverges and whether the rule is a published contract, a site setting or an unresolved policy. Keep only these allowlisted synthetic observations. Authentication material and whole service/config payloads do not belong in evidence.

Start with the original candidate and preserve adverse outcomes. A semantic assertion failure with its expected and actual values is evidence. A failed install, collection error, timeout or infrastructure failure gets its own outcome. A mutation kill requires a passing original and a failing relevant assertion after the deliberate edit. Preserve a surviving change and its exact selector as a coverage gap. Keep setup/collection evidence separate from numerical review results.
